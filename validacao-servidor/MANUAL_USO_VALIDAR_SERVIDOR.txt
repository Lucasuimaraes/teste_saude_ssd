VALIDAÇÃO DE SERVIDORES — v1.2.0
Debian 11 / SSD e HD SATA. Execute os comandos como root.

1. INSTALAR (primeira vez)

apt-get update && apt-get install -y git ca-certificates
git clone --branch master https://github.com/Lucasuimaraes/teste_saude_ssd.git /opt/teste_saude_ssd
bash /opt/teste_saude_ssd/validacao-servidor/instalar.sh
/usr/local/sbin/validar-servidor --instalar-dependencias

Se a pasta já existe, atualize. Pare se algum comando falhar.

2. ATUALIZAR (sem teste em execução)

git -C /opt/teste_saude_ssd pull --ff-only && bash /opt/teste_saude_ssd/validacao-servidor/instalar.sh
/usr/local/sbin/validar-servidor --versao

O instalador guarda backup da versão anterior.

3. EXECUTAR

Confira discos e interfaces:
lsblk -d -o NAME,MODEL,SIZE,TYPE
ip -br link

Consulta, sem stress:
/usr/local/sbin/validar-servidor --modo consulta --disco /dev/sda

Completo — somente em manutenção, com backup confirmado:
/usr/local/sbin/validar-servidor --modo completo --confirmar-manutencao --disco /dev/sda --cliente "Nome do cliente" --tecnico "Lucas"

Use o disco inteiro (/dev/sda), não a partição (/dev/sda1).
Para outro disco, repita --disco /dev/sdb.
Sem sensor CPU reconhecido, a carga é omitida. --permitir-sem-sensor exige supervisão externa.
O script não altera rede/firewall, não formata discos e não reinicia serviços.

4. TEMPO E RESULTADO

Contagem em HH:MM:SS, atualizada a cada segundo no terminal.
Mostra tempo decorrido, restante estimado e limite máximo.
Duração variável: não há previsão exata; o limite não é tempo esperado.
Previsão atingida: aguarda a ferramenta terminar, respeitando o limite.
SMART consulta o disco a cada 15 segundos, com contador entre consultas.

Durações principais:
- CPU/RAM inicial: 2 minutos.
- Memtester (2 passagens): variável, limite de 1 hora.
- Autoteste SMART: estimativa do disco; acompanhamento por até 15 minutos.
- CPU adicional: 10 minutos. RAM adicional: 10 minutos.
- Escrita em arquivo: 5 minutos.
As demais coletas dependem do equipamento. O total depende das etapas e placas.

Ao finalizar, o relatório COMPLETO aparece na tela, separado por etapas.
Cores: verde OK; amarelo atenção/inconclusivo; vermelho falha;
roxo não executado; azul/ciano informações e títulos.
COLETADO não significa APROVADO. Teste omitido não é teste aprovado.

Arquivos: /var/log/validacao-servidor/<execução>/
- RESUMO.txt: resultados por etapa.
- RELATORIO_COMPLETO.txt: resumo, comandos e todos os logs coletados.
- resultados.tsv e logs/: dados para diagnóstico.

Para reler, substitua <execução> pela pasta indicada ao finalizar:
less /var/log/validacao-servidor/<execução>/RELATORIO_COMPLETO.txt

Ctrl+C salva resultado parcial. Autoteste no firmware pode continuar.
Arquivos e saída redirecionada ficam sem cores. NO_COLOR=1 desativa cores.
Relatórios contêm dados do servidor: não publique no GitHub.

5. ETAPAS / REDE

1 Hardware | 2 Placas de rede | 3 CPU | 4 Memória | 5 Disco
6 Logs | 7 Serviços/Asterisk | 8 Rede/firewall | 9 Hora/NTP
10 Sistema | 11 Stress adicional

Selecionar etapas: acrescente --etapas 1,5,11 ao comando desejado.
Os testes de carga exigem --modo completo --confirmar-manutencao.

Segunda placa: cabo conectado e IP configurado. Substitua interface e destino:
/usr/local/sbin/validar-servidor --etapas 2 --interface eth1 --alvo-rede eth1=192.168.1.1

Vazão: em outro equipamento, execute iperf3 -s.
No servidor, acrescente --iperf-servidor IP ao comando completo.

6. CONFERÊNCIA FINAL

Revise alertas, falhas e testes omitidos. Teste chamadas, áudio, transferências,
filas e gravação. Confira backup, nobreak, cabos e ventilação.
EXT4 re-mounted/errors=remount-ro e SATA 3 Gb/s isolados não indicam defeito.

Códigos de saída: 0 coleta sem alertas automáticos; 1 revisar resultados;
2 erro de uso/preparação; 130/143 interrupção.
Todas as opções: /usr/local/sbin/validar-servidor --ajuda
